用 GitHub Pages 发布「家庭物品管理系统」

免费、自带 HTTPS、支持 PWA 安装。你的项目已用「相对路径 + .json 清单」，可直接托管，无需改代码。

一、先看结论

好消息：你的项目所有资源引用都是相对路径（./ 开头），没有以 / 开头的绝对路径。所以无论 GitHub 把它放在根路径还是子路径，都能正常加载，不需要改任何代码。
推荐：子路径 直接用现有仓库部署，最省事、零迁移成本。可选：根路径 想要更短的网址 https://你.github.io/ 时才需要（见下方选择）。

说明：PWA 的「全屏 + 离线 + 添加到主屏」与是否根路径没有关系，只取决于 HTTPS + 清单 + 图标齐全。子路径完全够用。

二、两种方式怎么选

方式仓库名访问地址适合场景
子路径（推荐）任意名称（如 family-items）https://你.github.io/family-items/直接用一个普通仓库部署，最简单；访问务必带末尾斜杠 /
根路径（可选）必须精确等于你.github.iohttps://你.github.io/想要很短的网址、或当个人主站时才用；每个账号只能有 1 个
如果你已经建好了仓库，直接走「子路径」即可，不用新建。只有确实想用 https://你.github.io/ 这么短的网址，才专门建一个名为 你.github.io 的仓库（账号里只能有这一个）。

三、上传文件（网页直接传，不用命令行）

1
新建仓库
登录 GitHub → 右上角 + → New repository → 填仓库名（建议 family-items）→ 选 Public（公开）→ Create repository。
2
上传根目录三个文件
仓库里点 Add file → Upload files，把 index.html、manifest.json、sw.js、.nojekyll 一起拖进上传区 → Commit changes。
3
上传 icons 图标（关键）
网页整文件夹拖放不稳定。最可靠做法：点 Add file → Create new file，文件名直接输入路径前缀：icons/icon-192.png → 粘贴文件内容 → Commit。对每个图标文件都这样建一次（icons/ 会被自动创建）。
4
启用 Pages
仓库 Settings → Pages → Source 选 Deploy from a branch → Branch 选 main、目录选 /(root) → Save。
5
等上线
首次约 1-5 分钟，页面顶部出现 Your site is published at …，即你的正式地址。

备选：git 命令行（更专业，可选）

# 在本地 PWA 文件夹内执行 git init git add . git commit -m "发布家庭物品管理系统 PWA" git branch -M main git remote add origin https://github.com/你的用户名/family-items.git git push -u origin main # 然后同样到 Settings → Pages 启用

没装 git 就直接用上面的网页方式，功能完全一致。

四、上传内容清单

PWA 家庭物品管理系统/ ├─ index.html 应用入口（主界面 + 快捷路由） ├─ manifest.json 应用清单（.json 后缀，浏览器按 application/json 识别） ├─ sw.js Service Worker（离线缓存） ├─ .nojekyll 禁用 Jekyll（保护 PWA 资产，显式采用） └─ icons/ ├─ icon-192.png 安装图标 192×192 ├─ icon-512.png 安装图标 512×512 ├─ icon-maskable-512.png 自适应图标（安卓动态图标） └─ apple-touch-icon.png iOS 主屏图标 180×180

五、在手机上安装为 App

1
安卓（Chrome / Edge）
用浏览器打开部署链接，首次加载后底部或菜单提示「添加至主屏幕 / 安装应用」；也可点菜单 ⋮ → 添加至主屏幕。
2
iPhone（Safari）
点分享 ↑ → 向下找「添加到主屏幕」→ 点「添加」。
3
启动
点主屏图标全屏运行，离线也能打开已缓存界面（首次需联网加载一次）。

六、⚠️ 常见坑与注意

1. 改了没效果 / 删不掉？这是 Service Worker 缓存 + 浏览器约 24h 更新周期。已升级缓存 v2 并做网络优先。发布后手机上第一次彻底打开、再关掉重开；若仍旧，强制刷新或清一次站点数据。 2. 子路径访问务必带尾斜杠：用 …/family-items/（末尾有 /），否则相对路径会解析错、资源 404。 3. 文件名大小写敏感：GitHub/Linux 区分大小写。Windows 本地不区分，上传后引用路径的大小写必须与文件名完全一致（尤其 icon-192.png / apple-touch-icon.png）。 4. 部署生效有延迟：push 后 GitHub 构建 + CDN 同步，最坏约 20 分钟，别着急误以为失败。 5. 仓库名别用特殊结尾：避免以 . 或 - 结尾即可（官方只明文禁止以 .git 结尾）。

七、发布前自检

✓
整个项目（含 icons/ 子目录和 .nojekyll）都上传，缺一不可
✓
容器/仓库名全小写，引用路径与文件名大小写完全一致
✓
得到以 https:// 开头的链接（GitHub Pages 强制 HTTPS）
✓
手机访问用带尾斜杠的完整地址
✓
手机打开后出现「添加至主屏幕」（安卓）或能通过分享添加（iPhone）
✓
点主屏图标全屏打开，开飞行模式仍能看到已缓存界面

八、以后如何更新

改完本地文件后，用网页在仓库里 Add file → Upload files 重新拖入覆盖同名文件，或 git push 到 main。GitHub 会自动重新部署，等构建完手机重开应用即拿到新版。

注意：若改动涉及 Service Worker 缓存策略，建议同步递增 sw.js 里的缓存版本号，确保手机拿到新逻辑。
